# 第 4 页：高 Ra 热对流为什么难算？

## 页面标题

**高 Ra 热对流为什么难算？**

## 页面怎么做

这一页用 **递进链条 + 右侧解释**。

左中部放四个蓝色图标卡片：

```text
Ra升高 → 边界层更薄 → 小尺度更多 → 计算量激增
```

每个卡片图标：

- Ra升高：温度计上升
- 边界层更薄：壁面附近细线
- 小尺度更多：小涡旋
- 计算量激增：上升柱状图

右边放 5 条解释：

```text
1 Ra 增大后，对流增强、边界层变薄、小尺度结构增多。

2 高 Ra 情况下流动往往非稳态，甚至出现复杂湍动特征。

3 为了分辨多尺度结构，需要更细网格、更小时间步和更长时间积分。

4 三维 DNS 中常见量级估计：总网格量随 Re 约按 Re^(9/4) 增长。

5 除计算量外，时序数据输出、统计平均与存储成本也会快速上升。
```

底部强调框：

```text
并行不是可选项，而是高 Ra 模拟的基础条件。
```

## 设计细节

标题左右两侧加短横线，横线外侧加蓝色点阵。这样更像你前面喜欢的标题样式。

# 第 6 页：为什么选择 LBM？

## 页面标题

**为什么选择 LBM？**

## 页面怎么做

这一页用你刚刚那种四步流程图比较好。

上半部分放 4 条要点：

```text
1 LBM 从介观分布函数出发，通过“碰撞—迁移”过程恢复宏观流动方程。

2 它不直接求解压力泊松方程，算法结构更适合规则网格上的大规模并行。

3 碰撞是完全局部的，迁移只涉及相邻格点，数据依赖短、通信模式清晰。

4 因此 LBM 对 OpenMP、GPU 加速和 MPI 区域分解都较为友好。
```

下半部分放流程图：

```text
分布函数 fi → 碰撞 Collision → 迁移 Streaming → 宏观量 ρ, u
```

注意图示：

- 分布函数：用 D2Q9，中心点 + 8 个方向向外。
- 碰撞：仍然用 D2Q9 方格，8 个方向都向中心碰撞。
- 迁移：用格点之间沿方向传播。
- 宏观量：只写 $ \rho, u $。

底部强调：

```text
高 Ra 热对流需要高效并行算法，而 LBM 的局部性正好契合这一需求。
```

# 四、你这套 PPT 的审美方向

我建议整套 PPT 最好遵循这几个原则：

```text
1. 不要大段文字堆满页面。
2. 每页只讲一个核心问题。
3. 技术页用流程图、耦合图、对比表。
4. AI 页用工作流图，不要做成产品介绍。
5. 校徽、Part 框、左侧蓝线、页码必须统一。
6. 红色只用于局限、风险和问题，不要滥用。
```

整体风格可以定为：

**“蓝白学术风 + 工程流程图 + 课堂经验分享”**
