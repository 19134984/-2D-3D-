# 多块网格代码：从一次粗步看懂接口交换

对应 `2DRBOpenaccMultiblock.F90`，2026-09-13。当前默认粗细比为 2，空间上保留 Huang 四点 Lagrange；交换的是碰撞前状态。原 `均匀网格/2DRBOpenacc.F90` 不修改。

## 先记住三件事

1. **每个块内部仍是均匀格子。** 中心粗块走一步，周围四个细块各走两步，最后到达同一个物理时刻。
2. **接口是人为切开的边界，不是固体壁面。** 缺少的信息从相邻块补；只有真实壁面才用原来的反弹边界条件。
3. **接收的数据还要参加碰撞。** 我们传递的是迁移后、下一次碰撞前的状态，不是碰撞后的 `f_post/g_post`。

## 三篇文献各采用什么

| 文献 | 本代码采用的部分 | 本代码没有直接照搬的部分 |
|---|---|---|
| Huang & Wu, PRE 89, 043303 (2014)，第 III 节式 (19)–(22) | 含力的非平衡矩重标定；四点空间 Lagrange；三时间层插值 | 论文的 D2Q9 温度模型；本代码继续用原 D2Q5 |
| Yu, Mei & Shyy, IJNMF 39, 99–120 (2002)，第 3 节 | 对齐节点、粗细双向传值、格距与时间步同比缩放，以及细步中间时刻需要边界数据的组织思想 | 三次样条与碰撞后分布转换 |
| Chen et al., Computers & Fluids 136, 228–246 (2016)，第 4 节、图 4 | 接收碰撞前状态，缓冲节点随后参加碰撞；宏观量在迁移后更新 | 无温度场情况下的薄缓冲布局、移动颗粒、该文特定的非水动力矩参数选择 |

这是结合文献原则、适配原 D2Q9/D2Q5 求解器的实现，不是三篇算法逐项拼接。Chen 的“碰撞前”与 Huang 的“迁移后”在状态上相容：上一次迁移完成后的 `f`，正是下一次碰撞的输入。

本地三篇全文在上一级 `pdf/` 文件夹。代码采用 Huang 的含力关系，不把 Yu/Chen 无该温度源修正的转换公式直接用于热分布。

## 一次粗步究竟做什么

以下时间以细格时间步为单位：细步为 1，粗步为 2。`itc` 是细步单位的整数时钟，只有两级同步后才增加 2。

设开始时两级都在 `t`。粗块上一时间层 `t-2` 已保存在历史数组中。

### 第 0 步：准备初始接口

第一次进入 GPU 数据区时，先从各块初始状态生成快照，再双向重建接口，最后更新快照。这样第一次碰撞也使用已准备的缓冲状态。

重启时直接恢复检查点中的同步状态与历史，不重复初始化。

### 第 1 步：粗块先预测到 `t+2`

调用 `advance_block(1)`。它的输入接口已经在上次同步或初始交换时准备好。

粗块按原来的完整顺序推进：

```text
流场碰撞 → 流场迁移 → 物理壁面处理 → 计算 rho、u、v、力
        → 温度碰撞 → 温度迁移 → 温度壁面处理 → 计算 T
```

得到粗块 `t+2` 的预测，并保存交换量。此时细块还在 `t`，因此粗块最外两层只是待修复缓冲，不能作为来源点；内部预测可以给细块使用。

### 第 2 步：细块从 `t` 走到 `t+1`

1. 给四个细块准备 **`t` 时刻**的接口。
2. 同级数据来自其他细块的 `t` 快照；跨级数据来自粗块保存的 `t` 快照。
3. 四个细块分别执行原 `advance_block`，到达 `t+1`。
4. 保存各细块 `t+1` 的交换量快照。

这里不能使用粗块 `t+2` 的值直接当作细块 `t` 的边界；目标时刻必须匹配。

### 第 3 步：细块从 `t+1` 走到 `t+2`

1. 给四个细块准备 **`t+1` 时刻**的接口。
2. 同级来源已经在 `t+1`，直接使用同级快照。
3. 粗块没有直接计算 `t+1`，用 `t-2、t、t+2` 三个粗时间层插值。
4. 接收完接口后，再碰撞、迁移，到达 `t+2`；保存细块快照。

对每一个已经完成空间取值的交换量 `Q`，中间时刻使用：

\[
Q(t+1)=-\frac18Q_c(t-2)+\frac34Q_c(t)+\frac38Q_c(t+2).
\]

第一次粗步没有 `t-2`，只在启动阶段改用：

\[
Q(t+1)=\frac12Q_c(t)+\frac12Q_c(t+2).
\]

代码的 `theta=(k-1)/refineRatio` 指细子步的**起点**。默认两个子步分别是 `theta=0、0.5`。

### 第 4 步：在 `t+2` 同步

1. 用细块内部数据修复粗块缓冲。
2. 更新粗块 `t+2` 快照，再补齐细块 `t+2` 缓冲。
3. 滚动粗时间历史，`itc` 增加 2。
4. 此时才能输出或写检查点。两级接口已经准备好，可供下一次碰撞使用。

细块最后保存的快照包含推进后尚未修复的缓冲值，但这些位置被来源筛选明确排除；实际可供传值的内部快照与同步时刻一致。

## 空间上接收哪些节点

默认 `overlapCells=2`，表示**各块从自身基准边界延伸 2 个粗格距**，即 4 个细格距。粗块先以左/下接口节点为锚点，将右/上基准边界向外补齐到完整粗格距，再添加重叠层；细块计算基准不动，统计分界另取粗块共址基准。因此总重叠宽度还包含两块基准边界之间原有的距离，不能统一写成 8。

以左细块与中心粗块为例：

| 内容 | x 坐标 |
|---|---|
| 物理积分分界，即从左墙向内第 128 个细节点 | 127.5 |
| 共同节点参考列 | 127.5 |
| 粗块计算起点 | 123.5 |
| 细块计算终点 | 131.5 |
| 粗块需要接收的两列 | 123.5、125.5 |
| 细块需要接收的两列 | 130.5、131.5 |
| 粗块可提供数据的内部 | 从 127.5 向右，排除其余方向的人工边界 |
| 细块可提供数据的内部 | 最右到 129.5，排除其余方向的人工边界 |

这个左侧重叠带跨度为 8，含边界共 **9 排细节点、5 排粗节点**。这不是“一次插值用 9 个点”。

右侧不同：细块基准边界仍为 `896.5`，粗块从左基准 `127.5` 按格距 2 排列，右基准向外补齐为 `897.5`。

| 内容 | x 坐标 |
|---|---|
| 右细块基准边界 | 896.5 |
| 粗块右基准边界，添加重叠层之前 | 897.5 |
| 中心与右细块共同的物理积分分界 | 897.5 |
| 右细块计算起点 | 892.5 = 896.5−4 |
| 粗块计算终点 | 901.5 = 897.5+4 |
| 粗块需要接收的两列 | 899.5、901.5 |
| 细块需要接收的两列 | 892.5、893.5 |
| 粗块可提供数据的内部 | 最右到 897.5，排除其余方向的人工边界 |
| 右细块可提供数据的内部 | 从 894.5 向右，排除其余方向的人工边界 |

右侧重叠带为 `[892.5,901.5]`，跨度 9；下侧与左侧同理，上侧与右侧同理。所有粗间隔仍为 2，没有不足一个粗格距的末端间隔。`blockBaseBox` 记录计算基准边界；`blockOwnedBox` 在 `127.5/897.5` 共址节点处划分积分面积，上细块从 `y=897.5` 开始积分，左右细块统计区域也统一到 `y=897.5` 为止，角部无重复或空隙。细块的计算基准仍保留原节点编号定义。

原 `图示/multiblock-interface.png` 为整数厚度定义下的历史布局图；当前节点编号定义的坐标以上表为准。

### 空间取值的三个例子

1. **完全重合：**细块目标 `(131.5,511.5)` 在粗块有同坐标节点，直接读取交换量。
2. **一个方向不重合：**细块目标 `(130.5,511.5)`，使用同一行的粗节点 `127.5、129.5、131.5、133.5`，权重是 `(-1,9,9,-1)/16`。
3. **两个方向都不重合：**细块目标 `(130.5,512.5)`，x 取上述四列，y 取 `509.5、511.5、513.5、515.5` 四行，二维权重为两个一维权重的乘积，共 16 个来源点。

`133.5` 在重叠带之外，但属于粗块内部，因此可以作为来源。四个或十六个来源点不必全部位于重叠带。

在角部，程序先寻找可用来源块，有合适的同级块时优先同级。所有候选来源都必须避开人工边界两层；不存在合规模板时直接报错，不做未经控制的外推。

### 为什么保留两层缓冲

流场迁移后，最外层人工边界的速度可能不完整；随后温度碰撞要使用速度，再经温度迁移，影响可能向内传播一层。因此保留两层缓冲来隔离这一依赖，内部算法顺序不变。

单纯从程序中删除一层，会改变这段依赖关系。Chen 的纯流场薄接口不能直接证明我们的热流耦合也能用一层。

左/下两块基准边界一致，以下来源范围下限仍需满足；右/上的向外补齐会增加重叠，但不放宽全局下限：

\[
2\,\texttt{overlap} \ge
\texttt{interfaceSkin}\,\texttt{refineRatio}+\texttt{interfaceSkin}-1.
\]

默认粗细比为 2、两层缓冲时，整数 `overlapCells` 至少为 2。这个范围条件之外，程序还逐节点检查实际四点模板。

## 交换的不是裸的 f、g

两级格距、时间步、松弛率不同，直接复制原始非平衡分布会破坏传输系数的一致性。

代码先把 `f,g` 转成宏观量及归一化的非平衡矩。以流场非守恒矩为例：

\[
K_a=\frac{s_{a,b}}{h_b}
\left(m_{a,b}-m^{eq}_{a,b}+\frac12F^{LB}_{m,a,b}\right).
\]

`encode_packets` 打包 22 个交换分量：`rho,u,v,T,Fx/h,Fy/h,Kf(9),Kg(5),dBx/h,dBy/h`。空间和时间插值都针对这些分量进行；`apply_packets` 用目标块参数重建：

\[
m_{a,d}=m^{eq}_{a,d}+\frac{h_d}{s_{a,d}}K_a
-\frac12F^{LB}_{m,a,d}.
\]

守恒矩按密度、速度及半步力修正恢复，再逆变换成分布。温度场使用对应的 D2Q5 矩，并传递 `B_prev` 对应的时间差，以保留原 `EnableUseG` 修正。这里没有 Yu/Chen 碰撞后转换中的 `1/(1-s)` 因子。

`B_prev` 的跨级处理是对原 D2Q5 离散时序的适配，三篇文献没有直接给出这份代码的完整温度接口公式；仍需用热场回归与收敛研究检验。

## 从哪里开始读代码

从 **`advance_multiblock`** 开始即可，不必先读碰撞矩阵。

| 函数 | 读它时只问一个问题 |
|---|---|
| `advance_multiblock` | 当前是谁在推进，起点时间是什么？ |
| `coarse_time_weights` | 细块需要哪个时刻的粗块数据？ |
| `exchange_interfaces` | 哪个块接收，哪个块提供？ |
| `donor_stencil` | 目标是否重合，来源是否避开缓冲？ |
| `encode_packets / interpolate_packets / apply_packets` | 原始分布如何变成公共量，再恢复为目标分布？ |
| `advance_block` | 收到的缓冲状态如何与内部节点一起碰撞、迁移？ |
| `calNuRe` | 如何只计一次物理面积？ |

积分使用独立的物理分区和裁剪面积权重，不是把所有计算节点都按 `h²` 相加。中心积分范围采用粗块共址基准边界，默认每方向 `[127.5,897.5]`，一维端点权重为 `1`、内部为 `2`，二维取乘积，等价于复合梯形积分。细网格层厚度无须被粗细比整除；靠墙细块的裁剪若不对称，仍在末两个积分节点间转移权重，保持总面积及线性坐标积分准确。重叠节点可以存两份状态，但物理面积不重复计算。

## 本次修改与验证边界

本次改动包括：首次碰撞前准备接口；每个细子步起点显式交换；同步点修复两级缓冲；默认单侧延伸改为 2 个粗格距；把错误的“四点插值至少延伸四粗格距”限制改为来源范围判据。块内碰撞、迁移、物理壁面公式保持原样。

重启标识更新为 `MB2DRESTART0004`，拒绝旧接口坐标定义的检查点。场快照结构仍为 `MB2DSNAPSHOT0002`。

可复现检查由 `verify_multiblock.py` 和 `transient_compare.py` 执行，结果及源码 SHA-256 记录在对应 JSON 中。它们覆盖 OpenACC host 编译运行、纯导热、单块回归、时间权重、重合/非重合传值、精确重启及低 Ra 瞬态，并比较同一新时序下的宽/窄重叠区。

这些检查不等于 P100/GPU 验证、长期统计收敛或严格守恒证明。高 Ra 稳定性、空间/时间收敛阶及长期质量漂移仍需进一步验证。
