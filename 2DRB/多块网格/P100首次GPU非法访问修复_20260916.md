# P100 首次 GPU 非法访问修复

日期：2026-09-16。修复 `2DRBOpenaccMultiblock.F90` 中 `interpolate_packets` 的时间权重传递；保留用户已删除 EnableUseG 的版本，其余数值公式与默认算例参数不变。

## 定位证据

首次正式任务 6972.master 编译成功，但异步执行在 bounceback 附近报告 CUDA_ERROR_ILLEGAL_ADDRESS。该位置是错误被发现的位置，不能据此修改反弹公式。

| 6974.master | 原源码、Ra=1e6、256²、ratio=2，只运行 2 个细步 | 同样非法访问，run.status=1 |
| 6975.master | 同一短算例，NVCOMPILER_ACC_SYNCHRONOUS=1 | 初始化中的 interpolate_packets 报错 |
| 6976.master | 原短算例，Compute Sanitizer memcheck | wt(k) 所在行 Invalid global read of size 8；575 个错误，run.status=99 |
| 6977.master | 只修复权重传入方式，保留 async(1)，同一 memcheck | 0 errors，run.status=0 |
| 6978.master | 修复版完整推进 40 细步、检查全部流场/温度分布有限性、导出场量 | run.status=0，与主机轨迹一致至舍入误差 |

6973.master 是诊断脚本准备失败：哈希清单含 CRLF，未运行求解器；不计作 GPU 复现。早期诊断 PBS 最后一条命令写状态文件，所以其 PBS exit_status 可能为 0；以上使用保存的求解器 run.status 与 sanitizer 输出判定。诊断提交器现已改为传播求解器退出码。

## 修复

原核使用数组形参 `wt(0:2)` 的 `firstprivate(wt)`；NVHPC 24.3 / P100 的该执行路径在访问 `wt(k)` 时发生非法地址读取。将主机端 `wt(0:2)` 取为局部标量 `wt0/wt1/wt2`，在 GPU 核中使用 `firstprivate(wt0,wt1,wt2)`，按时间层 k 选择对应权重。

这是当前编译器/设备组合下可重复验证的数据传递问题；未进一步断言其在 OpenACC 标准中的归责或其他编译器行为。没有改变空间插值、时间权重值、粗细步比、边界反弹、碰撞、热模型及后处理公式，也没有用全局同步掩盖错误。
