## 2. 代码风格的主要特征

1. **单文件容纳完整求解流程。** 文件前部放宏和共享数据模块，中部是主程序，后部按功能放外部子程序。主求解步骤通过 `use commondata...` 共享数组；插值、拟合、输出等辅助过程则会显式传参并标注 `intent`。
2. **参数集中、开关直观。** 算例、边界、稳态/非稳态、温度模型用文件头部 `#define/#ifdef` 选择；互斥组合用 `#error` 拦截。网格、Ra、Pr、Ma、松弛参数、重启和输出设置集中在模块中。
3. **物理名称与计算阶段直接对应。** `f/g`、`rho/u/v/w/T`、`Rayleigh/Prandtl/Mach` 保留数值意义；`collision/streaming/bounceback/macro` 直接对应 LBM 步骤，温度链加 `T`。
4. **公式展开可直接核对。** 矩变换、平衡矩、松弛系数、力项和逆变换分别书写，常见形式是显式标量表达式和局部小数组。后续修改某个矩或源项，优先在对应公式区增加明确表达式。
5. **中文解释细，分段明显。** 大段使用 `!====` 或 `!----`；子程序头写“子程序／作用／用途”，正文解释物理意义、索引、边界和调用时机。MPI 部分还逐项解释接口参数。
6. **精度和中间状态显式。** 主要采用 `implicit none`、`real(kind=8)`、`integer(kind=4)`、`1.0d0`、`dble(...)`；局部值常用 `Loc`，碰撞后状态用 `_post`，历史状态用 `_prev`，MPI 全局汇总用 `_all`。
7. **计算、诊断和续算都放进程序框架。** 求解器包含收敛历史、Nu/Re、Tecplot、宏观场快照、分布函数重启和运行设置日志，便于算例复现与比较。

缩进和大小写并非四份文件完全统一：二维主体多为四空格，三维主体多为两空格，也混用点式比较与符号比较。新增代码应跟随修改位置附近的习惯，不为统一外观重排整份源码。

## 3. 文件结构与主推进流程

```text
文件头：模型、坐标约定
宏开关：算例／边界／算法／并行模式及组合检查
commondata...：参数、派生量、数组、计数器、文件前缀
program main...：后端初始化 → 初始场/重启 → 时间循环 → 诊断 → 释放
initial...：坐标、分配、格子常量、场初始化、重启恢复、运行设置
流场子程序：collision → streaming → bounceback → macro
温度子程序：collisionT → streamingT → bouncebackT → macroT
check / calNuRe：收敛与时间序列
output / reload：可视化、快照、重启、元信息
算例后处理：热流、壁面 Nu、速度极值、切片、流函数/涡量
辅助子程序：拟合、插值、二进制输出
```

共同主循环可概括为下列调用序列。单 GPU 文件中相应名称带 `3d`；这只是结构示意，不是独立可编译模板。

```fortran
itc = itc + 1

call collision()
! MPI 版本在这里调用 exchange_f_post_halo_mpi()
call streaming()
call bounceback()
call macro()

call collisionT()
! MPI 版本在这里调用 exchange_g_post_halo_mpi()
call streamingT()
call bouncebackT()
call macroT()

! 按累计步数或目标采样时刻进行 check / calNuRe / 输出
```

这一定序也是耦合语义：流场碰撞读取当前温度；更新流场宏观量之后，温度碰撞读取更新后的速度和本步温度更新前的 `T`。`EnableUseG` 的历史量在温度碰撞阶段参与差分并更新。新增耦合项必须说明读取的是哪个阶段的状态，不能只看变量名就移动调用位置。

入口定位：[二维 main](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/2DRBOpenmp.F90:258)、[三维 CPU main](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenmp.F90:289)、[单 GPU main](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenacc.F90:283)、[MPI main](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenaccMpi.F90:378)。

## 4. 数组、索引与命名约定

| 项目 | CPU 版本 | GPU / MPI + GPU 版本 |
| --- | --- | --- |
| 二维分布函数 | `f(alpha,i,j)`、`g(alpha,i,j)` | 本说明的四基准中没有二维 GPU 文件 |
| 三维分布函数 | `f(alpha,i,j,k)`、`g(alpha,i,j,k)` | `f(i,j,k,alpha)`、`g(i,j,k,alpha)` |
| 宏观场 | `u(i,j[,k])` 等独立数组 | 相同形式；MPI 空间范围为局部块 |
| 方向范围 | 二维 `0:8` / `0:4`；三维 `0:qf-1` / `0:qt-1` | 三维相同方向编号 |
| 有效流体点 | `1:nx`、`1:ny`、`1:nz` | 单 GPU 为全域；MPI 为 `1:xLocalCount` 等 |
| 碰撞后缓冲 | `f_post/g_post` 空间方向含 `0:N+1` | 相同的一层 ghost 设计，MPI 用局部长度 |

Fortran 首维连续，因此 CPU 的同一格点方向分量相邻，GPU 的同一方向空间点按 `i` 连续；这是源码中实际存在的布局区别。GPU 布局有利于相邻空间线程访问同一方向的数据，这是实现意图的解释，不是本次测得的加速结论。

常见循环为二维 `j → i → alpha`、三维 `k → j → i → alpha`；矩变换中方向表达式通常直接展开。MPI 的场汇总／重启打包则常用 `alpha → k → j → i`。循环顺序应根据实际子程序和后端继承。

| 名称 | 实际含义 |
| --- | --- |
| `m/meq/m_post/s/fSource` | 流场矩、平衡矩、碰撞后矩、松弛率、矩空间源项 |
| `n/neq/n_post/q` | 温度矩、平衡矩、碰撞后矩、松弛率；这里 `q` 不是方向数 |
| `qf/qt` | 三维流场／温度格子的方向总数 |
| `up/vp/wp/Tp` | 上一次收敛检查保存的宏观场，不是每步都更新 |
| `Bx_prev/By_prev/Bz_prev` | 上一次温度碰撞阶段的 `uT/vT/wT`，服务于 UseG 修正 |
| `itc/restartItcOffset` | 本次运行段步数／重启前累计步数 |
| `dimensionlessTime` | Nu/Re 样本计数器，名字虽含 Time，变量本身不是连续物理时间 |
| `xStartGlobal/xLocalCount` 等 | MPI 局部块的全域起点／本地长度 |

## 5. 必须保留的物理与离散约定

| 约定 | 二维 | 三维 |
| --- | --- | --- |
| 浮力／竖直方向 | `y/j/v` | `z/k/w` |
| 侧壁差温热流方向 | `x/i/u`；特征长度 `nx` | `y/j/v`；特征长度 `ny` |
| RB 冷热壁法向 | `y/j`；特征长度 `ny` | `z/k`；特征长度 `nz` |
| `HorizontalWalls*` | y 法向壁 | z 法向壁 |
| `VerticalWalls*` | x 法向壁 | y 法向壁 |
| `SpanwiseWalls*` | 无 | x 法向壁 |

内部节点坐标使用 `(i-0.5)/lengthUnit` 等形式，物理壁面位于 `0` 和 `N/lengthUnit`。邻壁流体点距物理壁面半个格距，这与反弹边界、壁面热流差分和后处理插值共同构成几何约定。

流场采用“矩正变换 → 平衡矩 → 松弛系数 → 半步修正源项 → 矩碰撞 → 逆变换”。速度恢复包含半步力项；二维力主要保存在 `Fx/Fy` 数组中，三维用 `FxLoc/FyLoc/FzLoc` 等局部量。迁移是 pull：从 `i-ex(alpha)` 等上游索引读取 `_post`，随后边界过程重写壁面入射分量。

温度模型分支会一起改变权重、平衡矩、松弛参数和恒温边界系数。`EnableUseG` 分支还计算 `B-B_prev` 并作用于通量矩。因此修改温度算法时，应联查模块参数、格子初始化、`collisionT`、`bouncebackT` 和重启状态。

从源码可读出的参数链为：`Rayleigh/Prandtl/Mach/lengthUnit → tauf → viscosity → diffusivity → 温度松弛参数`，再由浮力尺度得到 `timeUnit` 和 `velocityUnit`。默认 `Thot-Tcold=1`。拓展温差、方向或标度时需要重新核对参数和 Nu 定义，不把默认设置当作任意情形的公式。

## 6. 并行版本各自的组织习惯

### OpenMP

- 在具体计算子程序的网格循环上放指令，使用 `default(none)`，明确列 `shared/private`。
- 二维常在外层 `j` 循环并行；三维体循环常见 `collapse(3)`，壁面循环常见 `collapse(2)`。
- `m/n/s/q` 等格点临时数组放入 `private`；收敛、热流、速度平方和采用 `reduction`。
- 当前主程序显式设置 24 线程。后续可以按算例机器配置调整，它是本版本运行参数，不是必须固定的代码风格。

### 单 GPU OpenACC

- 主机完成初始化／重启，`enter_data_3d_openacc` 让主要数组常驻 GPU。
- 初始状态和格子常量用 `copyin`，碰撞后中间缓冲用 `create`；运行核函数以 `present` 明确数据依赖。
- 主要推进核使用 `gang vector collapse(3)` 与 `async(1)`；检查、归约和主机输出之前按路径等待。
- 快照同步 `u/v/w/T/rho`，Tecplot 同步 `u/v/w/T`，重启同步 `f/g` 及所需历史量，避免每步搬回全场。
- 先 `exit data delete`，再释放主机数组。

数据生命周期入口：[enter/update/exit data](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenacc.F90:841)。

### MPI + OpenACC

- `MpiDecomp1D/2D/3D` 对应 z-slab、y/z pencil、x/y/z block；分块余数优先分给前面的坐标，避免要求网格整除。
- 2D/3D 分解候选先比较局部块形状，再用估计通信面面积作并列裁决。
- 以 `COMM3D` 的坐标、邻居和 rank 为准；节点内 rank 通过共享内存通信器取得，再绑定 GPU。当前实现要求一 GPU 一 rank，并检查节点／设备数量。
- 使用 `has*Boundary` 区分真实物理壁面和分区界面。周期性由笛卡尔拓扑及 halo 实现；同方向速度／温度周期宏需配对。
- 流场每个面只打包 D3Q19 中跨面的 5 个方向；按 x→y→z 顺序交换，后续面带上先前收到的 halo，传播斜向所需的边线数据。D3Q7 每个面只需 1 个方向。
- GPU pack/unpack 与 `host_data use_device`、`MPI_SENDRECV` 组成通信路径，依赖支持设备缓冲的 MPI。当前推进核没有单 GPU 版的 `async(1)`，不能声称已实现计算通信重叠。
- 残差的四个求和量、Nu/Re 的两个求和量分别打包做 `MPI_ALLREDUCE`，之后才计算全域比值。
- 输出时把局部场汇总到 root 的 `*_all`；重启由 root 读取全域状态并分发局部块。全场汇总不是每一步都做。非 root 使用独立设置日志。

入口：[拓扑与设备绑定](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenaccMpi.F90:615)、[halo](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenaccMpi.F90:1818)、[全域残差](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenaccMpi.F90:2604)、[输出汇总](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenaccMpi.F90:2755)。

## 7. 收敛、统计和输出约定

**稳态。** 主循环同时检查速度和温度阈值，并有最大步数上限；当前每累计 2,000 步调用一次 `check`。速度指标是本次检查与上次检查之间的相对 L2 变化，温度指标是相对 L1 变化。它们不是对解析解的误差，也不是“相邻两个格子步”的误差。三维版本对分母接近零有兜底，二维当前直接相除。

**非稳态。** `unsteadyRunDuration` 控制总自由落体时间，重启时仅推进剩余步数；采样时刻按绝对目标时间换算为格子步。后处理重新读取完整 `.dat` 历史，输出序列、累计平均、指定窗口及前后半段平均，并检查行数与 Nu/Re 时间列是否一致。

**Nu/Re。** 时间序列中的 Nu 用体平均对流热流加导热基值；Re 用全域 RMS 速度。`Nu_global` 另显式计算对流项与温度梯度；壁面 Nu、中面 Nu、局部 Nu 极值则由各自子程序计算，不能只按名称把这些量混为一列。

**极值和截面。** 二维中心线速度使用五点最小二乘抛物线细化；三维 `calc_*mid_max_common` 是插值到中心面后扫描离散点的最大值。三维壁面 Nu 极值是在一个切向平均后的剖线上寻找，不能称为整个二维壁面上的点态极值。二维流函数另有累积积分和样条细化；三维提供三个中面的流函数／涡量诊断切片。

| 文件类型 | 内容与约定 |
| --- | --- |
| `SimulationSettings*.txt` | 网格、物理参数、模型分支、边界、输出设置、重启信息、耗时和诊断 |
| `convergence*.plt` | 收敛变化量及累计格子步；汇总文件用算例标签区分 |
| `Nu_VolAvg*.dat / Re_VolAvg*.dat` | 时间序列；当前稳态时间列用累计格子步，非稳态时间列用自由落体时间 |
| `*Snapshot-*.bin` | 宏观场快照，速度乘 `velocityScaleCompare`；用于后处理 |
| `reloadFile*-*.bin` | 原格子状态 `f/g`，UseG 分支另含历史量；用于恢复计算 |
| `*-latest.meta` | 版本、流动模式、网格、最新文件名、累计步数／时间及各类编号 |
| 三维 `*-fullField-*.plt` | 坐标已按长度标度输出；速度写原格子值 |
| 三维 `*-midX/midY/midZ-*.plt` | 中面速度乘 `velocityScaleCompare`，变量名含 `*_nd` |

因此即使都叫“速度输出”，三维全场 `.plt` 与切片／快照的速度标度也不同。新后处理应显式记录变量定义和标度。

性能日志同时提供 CPU 时间与墙钟时间；MPI 总吞吐分母用最慢 rank 的墙钟时间。主循环内启用的检查与周期输出也位于计时区间，不能直接把该 MLUPS 称为纯碰撞核性能。

## 8. 后续新增算法时的修改位置

| 任务 | 主要修改位置 | 必须联查的内容 |
| --- | --- | --- |
| 改流场碰撞／力项 | 模块参数、`collision`、`macro` | 初始平衡态、半步力、重启宏观量重构、守恒量 |
| 改温度碰撞／修正项 | 模块参数、`collisionT` | 温度权重、平衡矩、恒温边界、`macroT`、历史量 |
| 改边界 | 对应 `bounceback/bouncebackT` 宏分支 | 半格点几何、方向编号、角／边位置、Nu 差分和周期配套 |
| 增加有历史的量 | 模块声明、`initial`、更新子程序 | 分配／释放、GPU 驻留、重启读写、重启前后时间层 |
| 改格子或空间 stencil | 格子常量、碰撞和迁移 | ghost 厚度、MPI 方向集合／缓冲长度、边界、输出维数 |
| 新增验证量 | `check` 或独立诊断过程 | 指标定义、参考解、范数、单位、MPI 全局归约 |
| 改 CPU/GPU 数据布局 | 所有访问分布函数的位置 | 初始化、kernel、halo、重启打包，不能仅改 `allocate` |

后续实现默认按以下方式进行：

1. 先选最近的维度、方法和后端基准，明确所用版本及本次算例参数。
2. 沿用单文件主体、共享模块、八步推进接口、现有变量命名和中文子程序说明。
3. 把新方法放在对应阶段，给新增参数写清物理意义、适用范围及来源；宏分支保持可读、可检查。
4. 选取与该任务有关的诊断和输出。小型算法验证可以只启用必要输出，但保留可追踪的设置、结果与停止原因。
5. 比较新旧算法时对齐网格、物理参数、初值、边界、停止条件和输出标度；精度／守恒、稳定性和性能分别验证。
6. 新增状态必须走完初始化、时间更新、并行可见性、必要通信、重启和清理的生命周期。

若算法确实需要改变更新顺序、变量定义或程序结构，应先说明数学原因和影响，再做局部清晰的改动；“沿用风格”不等于固定旧算法的数值假设。

## 9. 本次对照发现的复用注意项

### 单 GPU 右侧无滑移壁存在静态不一致

[3DRBOpenacc.F90:1340](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenacc.F90:1340) 在 `VerticalWallsNoslip` 的 `j=ny` 面写为：

f(i,ny,k,16) = f_post(i,ny,k,15)
f(i,ny,k,18) = f_post(i,ny,k,17)

同文件 [opp 表](/Users/Admin/Documents/References/-2D-3D-/2DRB/均匀网格/3DRBOpenacc.F90:929) 给出的反向索引是 `opp(16)=17`、`opp(18)=15`；CPU 和 MPI 的相应无滑移分支也使用 `16←17`、`18←15`。这是已确认的源码映射差异；对运行结果的影响尚未测试。本次未修改，应在将单 GPU 版本用于新算法基线对照前核查。

### 标度与诊断集合并非完全一致

- 单 GPU 的 `calNuRe3d` 使用 `v*T` 或 `w*T`，乘 `velocityScaleCompare`；CPU/MPI 使用 `T-Tref` 和 `lengthUnit/diffusivity`。默认 `Tref=0`、比较标度为 `L/kappa` 时表达式一致，改标度／参考温度时不能假定仍一致。
- CPU 和 MPI 三维版额外包含侧壁加热的 `Nu_zmid`、指定中心线 `u/v` 极值与平均动能诊断；本次单 GPU 主程序没有同样的调用集合。
- 注释中的“收敛后诊断”不等于已确认满足收敛阈值：主循环也可能达到步数上限。后续验证应记录实际退出原因。

这些条目用于避免把版本差异当作统一风格，不是本次完成的修复或完整缺陷清单。
