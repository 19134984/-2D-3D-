# P100 服务器提交、续算与验收操作手册

日期：2026-09-16。用途：供另一个聊天窗口接手 2DRB / LBMCDE GPU 计算。本文依据仓库实际用过的 PBS 与提交脚本整理；**作业编号和节点空闲情况必须实时查询，不沿用旧聊天的状态。**

本文只记录操作流程，不授权新计算、删数据或修改已排队任务；具体算例与参数以用户当前要求为准。密码不写入文档、脚本、仓库或记忆。

## 1. 最重要的约定

1. 新提交用提交当时最新的本地对应算法源文件，不拿远端旧 `source/` 当母版。已经排队、正在运行的源快照不得静默替换。
2. 每个算例独立目录。续算优先新建目录，保留原轨迹、来源和检查点，不能覆盖正在写入的目录。
3. 分别核对实际源码、运行设置和 restart metadata 的网格与参数；目录名不是证据。曾出现名称 `grid2049`、实际源码却是 2048 的错误。
4. PBS 从 master 提交；GPU 计算用 node05/node07，不在 master 运行求解器，不干扰其他用户任务。
5. 独立扫描点可以在前一点失败后继续；同一轨迹续算必须有可信、有限且兼容的检查点。
6. 编译成功、退出码为 0、无非数、完成时长、统计收敛是不同判断。
7. 用户只要求提交时，提交后做一次队列和配置核查即可，不持续等待计算完成。

## 3. 选对算法与存储位置

| 第二套：温度 D2Q9-BGK | `Xs/D2Q9TRT_D2Q9BGK/2DRBOpenaccLBMCDE_D2Q9TRT_D2Q9BGK.F90` | `/data2/XLLi/LBMCDE/THRERMAL-D2Q9BGK-TEST/` |
| 第三套：温度 D2Q9-TRT | `Xs/D2Q9TRT_D2Q9TRT/2DRBOpenaccLBMCDE_D2Q9TRT_D2Q9TRT.F90` | `/data2/XLLi/LBMCDE/THRERMAL-D2Q9TRT-TEST/` |

远端 `THRERMAL` 为现有拼写，不能自行改为 `THERMAL`。源文件名含 `D2Q9TRT` 不代表实际流场一定是 TRT，应看宏。

流场分类：`FLOW_ODD_ORIGINAL_MAGIC`（原始）、`FLOW_ODD_EFFECTIVE_MAGIC`（修正）、`FLOW_ODD_FIXED_SQ`（固定 Sq）、`FLOW_BGK`。第一套对应目录常为 `ORIGINAL`、`EFFECTIVE`、`FIXED_SQ1`、`FLOW_BGK`。

推荐算例结构：

```text
<绝对算例目录>/
  source/               # 参数化源快照、来源记录
  results/              # 输出、检查点、实际编译哈希
  run.pbs               # 或 run_resume.pbs
  provenance.md         # 本地来源、参数改动、seed、提交编号
```

不要把其他套数的结果混进同一汇总；也不要为整洁擅自移动在途目录。

## 4. 提交前准备

### 4.1 先查状态，防止重复提交

在 master 上只读查询：

```sh
date
qstat -u xlli
pbsnodes node05 node07
qstat -f <待核对的作业ID>
```

`<...>` 均为占位符，必须替换，不可原样运行。结合 PBS 的资源分配判断，不只看 GPU 某一瞬间利用率。不得未经授权取消、迁移或修改其他作业。

### 4.2 建立参数清单与源快照

至少记录：套数、流场宏、Ra、Pr、Mach、nx/ny、chi_nu、chi_kappa、chi_b、Sq 策略、启动方式、总目标 tff、采样间隔、非数检测间隔、统计窗口、节点、walltime。

从最新本地母版复制到新算例；只做用户授权的参数化，不改母版既有参数。确认互斥流场宏没有同时启用。从零启动不能误启用 restart，续算不能误用静止初场。

记录三层 SHA-256：

1. 提交时本地母版；
2. 参数化并完成换行规范化后的算例源；
3. PBS 实际编译前记录的源。

第 2、3 层应一致。第 1 层通常因参数变化而不同，要保存差异说明，不能只凭哈希猜测算法是否改变。

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '<本地源文件绝对路径>'
```

上传用短脚本和明确路径，避免复杂嵌套的 PowerShell/SSH 引号：

```powershell
& 'C:/msys64/usr/bin/scp.exe' '<本地源文件绝对路径>' 'xlli@10.169.174.118:<远端算例绝对路径>/source/'
& 'C:/msys64/usr/bin/scp.exe' '<本地PBS绝对路径>' 'xlli@10.169.174.118:<远端算例绝对路径>/'
```

远端先创建准确的 `source/` 与 `results/`；PBS 的输出目录需要在提交前存在。上传后对 shell/PBS 做 `dos2unix`，执行 `bash -n <PBS路径>`，再核对源文件哈希。若对源也做了换行转换，须在转换后建立最终算例哈希。

从 PowerShell 管道传入短 shell 检查脚本时可能带 CRLF，可使用远端 `tr -d '\r' | bash`；更稳妥的是上传脚本后 `dos2unix` 再执行。

## 5. PBS 配置和执行检查

参考真实用过的文件（不是可不加检查直接复用的通用脚本）：

- [第二套 300→1000 PBS](../运行脚本/run_cases/F2_FLOW_BGK_Ra1e10_restart300_t1000_grid2049/chi0.7/run_resume.pbs)
- [第二套独立任务串行提交脚本](../运行脚本/tools/submit_d2q9bgk_ra1e10_t300_historyfix.sh)

它们的算例路径、chi、seed 时间和样本数已经写死。新任务复制后必须逐项修改并检查，不能直接再次运行旧提交脚本，否则会重复提交旧算例。

既有 PBS 头部示例：

```sh
#PBS -N <短作业名>
#PBS -q batch
#PBS -l nodes=node07:ppn=1
#PBS -l walltime=96:00:00
#PBS -o /data2/XLLi/<项目>/<算例>/results/pbs.stdout
#PBS -e /data2/XLLi/<项目>/<算例>/results/pbs.stderr
```

96h 是既有设置，不是保证当前队列都接受的通用上限。`ppn=1` 也不自动保证 GPU 独占，应根据实际调度配置和其他任务占用检查；两个节点可分别建串行任务链。

求解器运行环境沿用：

```sh
export OMP_NUM_THREADS=1
export ACC_DEVICE_TYPE=nvidia
export CUDA_VISIBLE_DEVICES=0
```

若调度器已有明确 GPU 绑定，应服从分配，不盲目覆盖。PBS 必须 `cd` 到绝对 results 路径，再编译/运行；源、输出、日志路径都不能依赖碰巧的提交工作目录。

需要保存：`job_identity.txt`、`timing.txt`、`runtime_source.sha256`、`compiler_version.txt`、`build_flags.txt`、`compile.log`、`compile.status`、`solver.stdout`、`run.status`、`pbs.stdout`、`pbs.stderr`。编译失败不得继续启动旧可执行文件。

既有脚本会在求解器退出后额外扫描 `Error:` 和非数，必要时把结果标为非零退出码（例如 86/87）。**这种结束后扫描不是实时非数终止机制**：要尽早停掉发散计算，必须检查求解器自身非数检测/退出逻辑及实际间隔已启用。

## 6. 排队：独立扫描与续算分清楚

单任务：

```sh
qsub /data2/XLLi/<项目>/<算例>/run.pbs
```

同一节点依次运行的**独立**扫描点，允许前一个失败后继续：

```sh
qsub -W depend=afterany:<前一任务ID> /data2/XLLi/<项目>/<下一个算例>/run.pbs
```

`afterany` 的意义是前序无论成功失败都结束后启动。它本身不检查前序输出质量。

真正依赖前一结果的同一轨迹续算，一般用 `afterok:<前序ID>` 加检查点预检。即使 afterok 通过，也不能跳过源/网格/非数检查；若前序因 walltime 非零退出，则应先验收现有 checkpoint，再决定恢复流程，不能直接把依赖改成 afterany 强行启动。

提交后记录返回的完整作业 ID，并用 `qstat -f <ID>` 核对节点、依赖、输出路径、walltime、状态。`H` 可能是依赖等待，也可能是其他 hold，必须看详情。

用户要求“提交后不用等”时，确认任务已正确排队后报告 ID、参数、节点和目标时长，结束本轮，不循环监测。

## 7. 续算操作：不能只复制一个 bin

### 7.1 检查 seed

- 读取 seed 的 `latest.meta`，确认实际 nx/ny、time_tf、累计采样数及引用的 `reloadFileName`。
- 找到 metadata 真正指向的二进制文件，不凭文件名大小或更新时间猜哪个是最新。
- 检查来源套数、流场宏、物理参数是否匹配；受控跨参数 restart 是特例，必须用户明确授权并另立实验记录。
- 检查 checkpoint 对应轨迹的非数记录及格式兼容性；确认二进制状态有效。仅 grep 文本不能证明全部二进制分布函数有限。
- 已经含 NaN 的 restart 不能继续；如果使用发散前的有限检查点，应明确是重试实验，不掩盖原轨迹发散。

### 7.2 同步恢复历史

至少包括：

```text
Nu_VolAvg_2DOpenaccLBMCDE_<模型>.dat
Re_VolAvg_2DOpenaccLBMCDE_<模型>.dat
DissipationHistory_2DOpenaccLBMCDE.dat
TemperatureProfileHistory_2DOpenaccLBMCDE.bin
PopulationNonequilibriumHistory_2DOpenaccLBMCDE_<模型>.dat
第一套还有 FlowOddMomentHistory_2DOpenaccLBMCDE_D2Q5.dat
对应 latest.meta 和它引用的 restart .bin
```

`<模型>` 按实际源码和文件名确定，不盲目替换。保存 `input_restart.sha256`、seed 路径、seed 的运行状态及源哈希。

正常完成到 300、从 t=0 每 1 tff 保存一次的轨迹，可能对应 301 个样本。**这是具体配置，不是通用固定值。** 要根据历史起点、采样间隔和端点规则计算。

walltime 中断时，历史可能比最新 checkpoint 更晚。只能在新的续算目录内，把文本历史和二进制剖面历史同步恢复到 checkpoint 时间/样本数；二进制必须按实际记录格式处理，不能用文本截断方式。保留原目录以便复核。

既有 `run_resume.pbs` 要求 seed 的 `run.status=0`，适合正常完成阶段的续算，**不能原样用于 walltime 中断恢复**。后者需专门处理并验证 checkpoint，不是删掉这个检查就算完成。

### 7.3 设置新目标

核对源码中的目标时间是“从初始时刻计的总时长”还是“额外运行时长”。现有 300→1000 流程设置总目标 1000，不是再加 1000。保留其他未经授权的物理与数值参数。

## 8. 完成后验收与统计

按以下顺序检查：

1. 编译和运行状态、Error 日志、PBS walltime/退出原因。
2. 历史实际末尾时间是否达到目标；退出码 0 不代表到达目标。
3. 全历史非数、时间倒序、重复、缺段；检查采样间隔，不能跨缺段插值后当真实计算结果。
4. 设置文件、实际源宏/参数、编译源哈希、metadata 网格/时间/计数是否一致。
5. 对 Nu/Re 独立复算窗口统计；耗散和温度剖面另查同窗覆盖与样本数。

Re 定义：

\[
Re=\sqrt{\langle u^2+v^2\rangle_{V,t}}H/\nu.
\]

等时间间隔的瞬时 Re 记录应取 `sqrt(mean(Re(t)^2))`，不能直接算 `mean(Re(t))`。若采样不等间隔，应按时间权重统计。

默认总时长 T：比较 `[T/2,3T/4)` 与 `[3T/4,T]`，最终结果取后者。1000 tff 对应 500～750 与 750～1000；两个半窗样本数可能因保留终点相差 1。

半窗偏差为 `100*abs(first-second)/abs(second)`，输出 `%`；Nu、Re 均严格小于 1 才通过本项目半窗检查。相对 Zhang 的偏差为 `100*(result-reference)/reference`，保留符号。无非数或半窗通过不等于空间精度、物理解唯一性或永久稳定性已验证。
