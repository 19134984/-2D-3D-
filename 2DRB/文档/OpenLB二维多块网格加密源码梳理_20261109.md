# OpenLB 二维多块网格加密源码梳理

研究日期：2026-11-09。研究对象为本地 `openLB`，版本 `1.9r0`，Git 提交 `4b911c38b0f94b52eaed8639900aefa38910b687`。本报告依据该提交的实际源码静态阅读；未编译、未运行算例，因此下文所述实现机制与数值验证结论应分开。

先给结论：二维确实存在四叉树块加密，但当前两个二维示例分别采用 **cell-centered/Rohde** 和 **vertex-centered/简化 Lagrava** 两条路线。四叉树负责生成块和层级；分布函数如何交换由耦合算子决定。第六至十节专门梳理交换、时间推进和稳定性相关处理。所有“可能改善稳定性”的解释均属于对代码数值作用的分析，不等于该版本已通过高 Rayleigh 数热对流验证。

范围澄清：**OpenLB 本身支持非等温流动、传热和自然对流。** 本报告前述“两个二维示例”专指 `gridRefinement` 下两个圆柱流动示例，不包括 `examples/thermal` 下的热流示例。不能把“这两个加密示例没有接入温度场”理解成“整个 OpenLB 只能等温流动”。现成二维热对流入口及与网格细化的关系见第十节。

## 一、先区分三个对象

1. **四叉树决定哪里细化和块之间的层级关系。** 虽然类名统一叫 `Octant`、`OctreeRoot`，但模板 `D=2` 时每次分裂确实产生四个子块；`D=3` 才产生八个。二维分支由两个 `0..1` 循环构造子块，子块逻辑边长减半，`refinementLevel` 加一。[octant.h:434](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:434)
2. **实际求解对象是按分辨率分组的规则块。** 树叶转换为 `Cuboid`，每个层级有自己的 `CuboidDecomposition`、`Mesh` 和负载分配器；`RefinedMesh` 用向量保存各层。这是“树管理拓扑、块执行计算”的结构。[refinedMeshBlueprint.h:705](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:705)、[mesh.h:52](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:52)、[mesh.h:171](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:171)
3. **粗细网格数值耦合是另一层算法。** 四叉树本身保存原点、层级、进程和边界标记等信息，未保存 LBM 分布函数；二维 cell-centered 示例构造树之后由 `refinement::rohde::executeStep` 推进求解。不要把树的遍历、MPI 树信息交换与分布函数插值当成同一过程。[octant.h:123](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:123)、[cylinder2d.cpp:270](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/cellCentered/cylinder2d/cylinder2d.cpp:270)

## 二、二维四叉树如何生成网格

### 2.1 不是一棵覆盖全域的大树，而是一片树森林

`OctreeRefinedMeshBlueprint<T,D>` 保存 `_roots`。构造时先用 `blockExtent = voxelSize * rootSize` 划分几何包围盒；每个方向用 `ceil(ratio)+2` 扩展根块数量，并将额外长度对称分配到两侧。接着为根块建立 `OctreeRoot`，不相交的根块会被移除。每个根初始只有一个 level 0 叶子。[refinedMeshBlueprint.h:38](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:38)、[refinedMeshBlueprint.h:67](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:67)、[refinedMeshBlueprint.h:143](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:143)、[root.h:65](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:65)

参数应这样区分：

| 源码参数/成员 | 含义 | 易混淆之处 |
|---|---|---|
| `voxelSize` | level 0 的物理格距 | 不是最细格距 |
| `rootSize` | 初始每根块每个方向的格点数 | 有细化时要求为偶数 |
| `maxRefinementLevel` | 每棵树允许的最大局部细化层级 | 不是全域根块编号的编码深度 |
| `_refinementLevel` | 当前叶子的数值分辨率层级 | 未合并时也决定叶块的空间大小 |
| `logicalRef` / `_globalLogicalRefinement` | 根据根森林尺度得到的空间编码深度 | 用于根块 Morton/Hilbert 定位 |
| `_domainLevel` | 合并之后用于描述块空间范围的层级 | 可与数值分辨率层级不同 |

出处：构造参数与偶数约束见 [refinedMeshBlueprint.h:54](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:54)，根森林的 `logicalRef` 见 [refinedMeshBlueprint.h:85](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:85)，叶子逻辑尺寸 `2^(maxRefinement-refinementLevel)` 见 [octant.h:146](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:146)，`domainLevel` 默认返回 `refinementLevel` 见 [octant.h:466](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:466)。

### 2.2 用几何指示函数选块，递归补到目标层级

`blueprint.refine(indicator, targetLevel, padding)` 遍历根块，`root.refine` 则遍历当前叶子：若叶子层级小于目标值且与指示函数相交，就删除该叶子、把四个子叶插到原位置，再从新子叶继续判断。因此一次调用可以从 level 0 连续细化到 level 2，而不是每次只升一级。[refinedMeshBlueprint.h:282](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:282)、[root.h:325](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:325)

相交判定不是解析计算两个几何体的交集，而是恢复该叶块的物理坐标，然后在格点及 padding 范围内调用 `indicatorF`；只要一个采样点落入指示区域就选中。因此极细小几何区域可能受采样分辨率影响，这是从判定实现得出的限制。[octant.h:311](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:311)

这里有一个容易忽略的细节：`finalPadding = (_refinementLevel + 1 == _maxRefinement) ? padding : 1`。传入的 padding 只在即将进入全局最大细化层时生效，其余层固定用 1；它并不始终等于调用参数，也不按本次 `targetLevel` 判断。[octant.h:335](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:335)

### 2.3 `balance()` 补过渡层，邻居范围包含角方向

从实现来看，`balance` 的作用是建立相邻层级差不超过 1 的 **2:1 网格过渡**。局部阶段由最细层向上遍历，给细叶子的粗邻居补充需要存在的层级；跨根阶段交换这些请求，再补齐完整叶子集合。这里说的是算法意图及可见实现，没有运行结构一致性测试来证明所有输入都满足该不变量。[root.h:538](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:538)、[root.h:612](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:612)、[root.h:780](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:780)

二维 `getCoarseGlobalNeighbors()` 对 `x,y=-1,0,1` 的所有组合建候选粗邻居，包含对角方向和中心；局部邻居也采用二维笛卡尔积循环。因此这一平衡处理考虑角邻接，不只是左右上下四条边。[octant.h:753](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:753)、[octant.h:789](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:789)、[octant.h:715](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:715)

在 MPI 模式，`balance` 发送的是候选叶子的 ID 和细化层级，接收后恢复 `Octant`，最后调用各根的 `balanceBorders`。这一步属于建网格阶段的拓扑通信，和运行阶段交换 `f_i` 等物理数据应分开理解。[refinedMeshBlueprint.h:882](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:882)

### 2.4 Morton 是基础编码，Hilbert 是可选排序

二维 `calcIDFast` 将 x、y 的二进制位交错：`splitBy2(y)<<1 | splitBy2(x)`，这就是 Morton/Z-order 编码；`calcOriginFast` 用 `compactBy2` 反解。默认构造参数 `hilbert=false`。[octant.h:595](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:595)、[octant.h:502](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:502)、[refinedMeshBlueprint.h:54](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:54)

实现也提供二维 Hilbert 顺序/方向查表、Morton 与 Hilbert ID 转换及显式排序函数。其作用是树叶/根的空间排列，服务于局部性和分区；没有证据说明它直接改变粗细网格插值的稳定性。二维 cylinder 示例没有启用 Hilbert。[octant.h:107](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:107)、[octant.h:1029](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:1029)、[root.h:794](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:794)、[cylinder2d.cpp:63](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/cellCentered/cylinder2d/cylinder2d.cpp:63)

### 2.5 `coarse()` 是同分辨率块合并，不是把求解网格变粗

`coarse` 每次尝试合并 `2^D` 个兄弟；二维即四个。要求它们具有相同 `refinementLevel`、相同 `domainLevel` 和相同父空间原点；正常调用还要求进程相同。合并时保留一个记录、调用 `incDomainLevel()`、删除其余记录。[root.h:169](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:169)

`incDomainLevel()` 实际减少 `_domainLevel`，没有改变 `_refinementLevel`。生成合并块时，格距仍是 `h0/2^refinementLevel`，块边长格点数则乘 `2^(refinementLevel-domainLevel)`。所以这里的 `coarse` 是把相邻规则小块合成较大规则块以减少管理开销；不能据此认为实现了运行中的数值粗化或解限制操作。[octant.h:159](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:159)、[octant.h:212](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:212)

例如，四个 level 1 的 `8×8` 小块合并后成为一个 `16×16` 块，其格距仍为 `h0/2`，细化层级仍为 1。这个例子是上述尺寸公式的直接计算，不是实测输出。

## 三、从叶子到实际粗细网格的接口几何

### 3.1 每个层级独立，粗细接口额外建立粗分辨率覆盖块

`createCuboidDecomposition` 预先创建 level `0..maxRefinementLevel` 的容器，并令格距逐级减半。每个普通叶子按自己的数值层级生成一个 Cuboid；未合并叶子的每方向格点数保持 `rootSize`，因此细化一次，物理块边长减半、叶子数在二维乘四。[refinedMeshBlueprint.h:705](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:705)、[octant.h:170](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:170)

`markBorders()` 找出和更粗叶子接触的细叶子，设置 `_coarseBorderOctant`。这些细叶子除了自身的细块，还会在 `level-1` 额外生成一个粗格距覆盖块：格距乘二、每方向格点数除二，物理覆盖范围保持一致，并设置 `isCoarseBorder`。因此该实现不会只保留一个几何上完全不重叠的叶子平铺后就直接求解；粗细接口附近有专门的粗分辨率重叠计算区域。[refinedMeshBlueprint.h:964](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:964)、[root.h:685](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:685)、[octant.h:200](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:200)

边界标记采用的是 `getCoarseGlobalTouching()`，其候选范围按当前子象限选取；不要将它与用于平衡的整片 `3×3` 候选邻域混为一谈。[root.h:697](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:697)、[octant.h:938](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:938)

### 3.2 单元中心坐标需要半格移动

`addCuboid` 每细化一级都执行 `delta/=2`、`localVoxel/=2`、`innerOrigin-=delta/2`，然后按子象限加上块偏移。这个移动用于保持 cell-centered 的粗细物理覆盖一致，不能只把格距除二而沿用原来的首格点中心。建立对应粗覆盖块时又加回 `delta/2`。[octant.h:188](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:188)、[octant.h:202](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:202)

例如粗网格格距为 `h`、第一个单元中心为 `x0`，对应左子块首细中心为 `x0-h/4`，细格距为 `h/2`。于是粗单元左右两个细中心为 `x0-h/4` 与 `x0+h/4`。这由坐标公式推导；不是“粗细节点完全重合”的顶点型网格。

### 3.3 三类“缓冲”分别起什么作用

| 对象 | 在哪里设置 | 实际作用 |
|---|---|---|
| 细化选区的 `padding` | `blueprint.refine(...,padding)`；相交采样判定 | 扩大被选中细化的块范围；部分层被强制为 1 |
| 粗细接口的粗覆盖块 | `markBorders` 标记后由 `addCuboid` 生成 | 在细网格接口附近保留对应粗级块，供跨层耦合 |
| 每层块的 `overlap=3` | `RefinedMesh` 构造函数 | 为块周围存储/通信提供三层重叠区；不是树的 padding 参数 |

出处分别为 [octant.h:335](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:335)、[octant.h:202](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:202)、[mesh.h:171](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:171)。XML 和外部向量构造路径同样设置三层 overlap。[mesh.h:77](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:77)、[mesh.h:127](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:127)

运行时所需的接口层通过 `SuperIndicatorDomainFrontierDistanceF` 识别。它将格点转换成物理位置，沿上下文邻接方向检查整个分解区域的内外情况，再返回符合给定距离的格点层；检查的是分解区域前沿，不是简单地把每个 Cuboid 的四条外边都当作粗细接口。[indicator.h:32](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/indicator.h:32)

`buildDecompositionBase` 收集实际叶块时排除 `isCoarseBorder` 的覆盖块，避免把这些接口辅助粗块作为独立实体再加入基础网格索引。[mesh.h:57](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:57)

### 3.4 负载分配尽量让对应粗细块在同一进程/平台

`RefinedLoadBalancer` 用细块中心定位其粗块：存在粗块匹配时，细块沿用该粗块的 rank 和 platform，保存细本地编号到粗本地编号的映射；没有对应粗块的细块另外分配。因此“粗细接口尽量同进程计算”是实现中的明确设计。[loadBalancer.h:36](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/loadBalancer.h:36)、[loadBalancer.h:61](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/loadBalancer.h:61)、[loadBalancer.h:77](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/loadBalancer.h:77)

蓝图的基础负载分配沿现有叶序累计权重、达到目标份额后进入下一个进程。默认叶权重主要按 `2^level` 计入更细层的额外时间步，粗接口块及合并块另加权；这属于算量估计，不是稳定性滤波。[refinedMeshBlueprint.h:841](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/refinedMeshBlueprint.h:841)、[root.h:505](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:505)、[octant.h:640](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:640)

另有一个 `resolveMixedCuboidDecomposition` 辅助函数，按不同格距把混合块分组，再将与当前级相交的下一细级块粗化为当前级覆盖块。但二维四叉树示例使用的是 `blueprint.createCuboidDecomposition` 路径；不能把这个辅助函数当作该示例必经步骤。[decomposition.h:31](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/decomposition.h:31)、[mesh.h:174](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:174)

## 四、直接可读的二维示例与适用边界

### 4.1 建议优先阅读的入口

`examples/gridRefinement/cellCentered/cylinder2d/cylinder2d.cpp` 是本次“四叉树 + 块级求解”最直接的二维入口。其实际构造顺序是：

```text
定义流道和几何指示区域
  → OctreeRefinedMeshBlueprint<T,2>
  → refine(矩形区域, level=1, padding=0)
  → refine(扩展圆区域, level=2, padding=2)
  → balance()          补相邻分辨率过渡
  → markBorders()      标记需要粗覆盖块的细叶
  → reduceWeights()    对固体区域减少算量估计
  → loadBalance()      分配计算进程
  → coarse()           同分辨率兄弟块合并
  → RefinedMesh        建每层 cuboid、负载分配和 overlap
```

### 6.1 共用的空间、时间与松弛时间关系

两条示例路线均使用 `convectivelyRefineUnitConverter(...,2)`，即逐级将物理格距和物理时间步同时除二，保持物理黏度和参考密度等参数。新 `RefinedLattice` 在各层自动这样配置。[unitConverter.h:1593](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/unitConverter.h:1593)、[lattice.h:67](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/lattice.h:67)、[vertexCentered/cylinder2d.cpp:301](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/vertexCentered/cylinder2d/cylinder2d.cpp:301)

令 `c` 表示粗级，`f` 表示相邻细级，便有：

\[
\Delta x_f=\frac{\Delta x_c}{2},\qquad
\Delta t_f=\frac{\Delta t_c}{2},\qquad
u_{LB,f}=u_{LB,c}.
\]

利用源码中的 `tau = nu_phys / (dx^2/dt) / cs^2 + 1/2`，可直接推得：

\[
\nu_{LB,f}=2\nu_{LB,c},\qquad
\tau_f-\frac12=2\left(\tau_c-\frac12\right),\qquad
\boxed{\tau_f=2\tau_c-\frac12}.
\]

这里的 `tau` 是无量纲格子松弛时间，`omega=1/tau`。公式来自 [unitConverter.h:1262](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/unitConverter.h:1262)，不是为提高稳定性任意改动物理黏度。例如 `tau_c=0.6` 时，下一层为 `0.7`，再下一层为 `0.9`；物理黏度保持不变。这种对流尺度下，细化也不会自动降低格子速度和 Mach 数。

### 6.2 源码里的分布采用平移存储

OpenLB 的 `equilibrium::secondOrder` 返回标准二阶平衡分布减去权重 `w_i`，即存储量可写成 `f_i=F_i-w_i`；`computeFneq` 则计算 `f_i-f_i^eq`。因此下文沿用源码记号 `f_i`，非平衡量与标准未平移分布的非平衡量相同。移植时要保留各自求解器的密度恢复约定。[lbm.h:49](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:49)、[lbm.h:394](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:394)

## 七、四叉树二维入口实际使用的 Rohde 接口

### 7.1 接口传输的是哪些数据

演化耦合上下文使用 `NORMAL_TYPE` 和离散法向 `NORMAL`。粗单元和四个细子单元的对应位置由 `CELL_ID_COARSE`、`CELL_ID_FINE` 和 `CellCenteredFineCells::child()` 管理；四个象限用 `(-1,-1)、(-1,1)、(1,-1)、(1,1)` 表示，实际细数组索引是基点的 `0/1` 偏移。[fields.h:33](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/fields.h:33)、[superLatticeRefinement.h:134](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/superLatticeRefinement.h:134)、[cellCentered.h:41](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/cellCentered.h:41)

设法向 `n` 指向细域外侧，`c_i` 为离散传播方向。源码的粗到细规则是：

\[
f^{f,k}_i\leftarrow f^c_i,
\qquad i\ne0,\quad \boldsymbol c_i\cdot\boldsymbol n\le0,
\quad k=1,2,3,4.
\]

也就是同一个粗方向分布复制给四个子单元，条件包括沿接口切向的方向；静止分布 `i=0` 不在此循环中。该算子在粗碰撞之后执行。[rohde.h:47](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:47)、[rohde.h:329](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:329)

细到粗规则是：

\[
f^c_i\leftarrow\frac14\sum_{k=1}^{4}f^{f,k}_i,
\qquad i\ne0,\quad \boldsymbol c_i\cdot\boldsymbol n>0.
\]

即只回传由细域流出的方向分布，取四子单元的等权平均；不是把所有九个方向全部覆盖。[rohde.h:79](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:79)

这两个演化算子虽然读取了 `NORMAL_TYPE`，当前函数体没有依据 type 分开处理平面与角点，而是统一使用上述点积条件；平面/非平面的显式分支出现在后面的输出用插值算子里。因而不能额外推断出此处有专门的角点稳定化策略。[rohde.h:44](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:44)、[rohde.h:76](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:76)、[rohde.h:119](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:119)

例如平直接口 `n=(1,0)`：向右的三种 D2Q9 传播方向用于细到粗；向左及切向的五种非静止方向用于粗到细。若某个回传方向四个细单元的存储分布为 `0.10、0.12、0.14、0.16`，则粗格该方向取 `0.13`。这是对循环的数值示例，不是运行结果。

### 7.2 为什么接口处还要改 Dynamics

`makeCoupler` 不仅登记传输位置，还做了以下设置：

1. 用细域 frontier 的 `distance=0` 层和粗流体材料筛选粗单元，要求粗单元至少有一层有效邻域。
2. 对应四个细单元设置 `NoDynamicsWithFixedDensityAndVelocity`。
3. 粗接口单元及其法向邻居设置 `NoDynamicsWithBulkMomenta`，细域覆盖内的其他相应粗单元也禁止碰撞。
4. 域外的细 padding 设 `NoDynamics`。

见 [rohde.h:237](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:237)、[rohde.h:254](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:254)、[rohde.h:275](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:275)。这些 Dynamics 的碰撞部分均是 `collision::None`；这是“接口传输单元如何参加演化”的一部分，不是把这些位置设成反弹壁面，也不是把它们重置为平衡分布。[dynamics.h:50](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/dynamics.h:50)、[dynamics.h:65](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/dynamics.h:65)、[dynamics.h:97](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/dynamics.h:97)

### 7.3 完整的一个粗时间步

```text
advance(level l, time index n):
    执行本级边界/外部 preStepHook
    若是最细级：collideAndStream，返回
    粗级 collide
    CoarseToFineO：复制选定方向到细接口单元
    advance(l+1, 2n)
    advance(l+1, 2n+1)
    粗级 stream
    FineToCoarseO：平均选定方向回到粗接口
```

这是 [rohde.h:317](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:317) 的直接展开。多层时递归继续细分，level 0 走一步，level 1 走两步，level 2 走四步。`collide` 和 `stream` 内部仍执行各自的同级通信与边界后处理，不能只复制块内碰撞循环而略去这些阶段。[superLattice.hh:1107](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/superLattice.hh:1107)

### 7.4 输出时的密度/速度插值不是演化稳定器

`RefinedLattice::synchronizeForPostProcessing()` 先通信粗级数据，再调用 `CoarseToFineForPostProcessingO`，补齐细级接口单元供输出读取的 `rho,u`。VTK reporter 在写文件前调用它。[lattice.h:168](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/lattice.h:168)、[vtkReporter.h:67](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/vtkReporter.h:67)

平直接口使用一个粗侧邻点，以及沿法向锚定到细域内部的采样点：粗值与细值的差除以 `1.75`，再按子单元相对位置乘 `0.5` 或 `1.0`。非平直接口逐个非零法向分量构造插值，最后对各轴结果平均。这些常数出现在当前实现中；此处仅陈述实际操作，未单独证明其几何精度阶。[rohde.h:113](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:113)、[rohde.h:144](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:144)、[rohde.h:179](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:179)

最后的 `defineRhoU` 针对的是前述固定密度/速度的 NoDynamics 单元：`FixedDensity::define` 写外部 `RHO` 字段，`FixedVelocityMomentum::define` 写 `VELOCITY` 字段。它不是 Lagrava 那样重构所有演化分布，因此不能把此处插值描述成每步的抗振荡或正则化操作。[elements.h:367](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/momenta/elements.h:367)、[elements.h:1022](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/momenta/elements.h:1022)

## 八、简化 Lagrava：宏观量插值、非平衡缩放与回传滤波

### 8.1 真正缓存和交换的量

首先由 `InitializeO` 读取粗格的：

\[
\rho,\quad (u_x,u_y),\quad (f_0^{neq},\ldots,f_8^{neq}),
\qquad f_i^{neq}=f_i-f_i^{eq}(\rho,u),
\]

缓存为 `PREV_RHO、PREV_U、PREV_FNEQ`。二维 D2Q9 的历史物理数据共 `1+2+9=12` 个标量，另外有粗细索引、法向和邻居上下文索引。这里保存的是完整九方向非平衡分布，不是只保存应力的二阶矩。[lagrava.h:34](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:34)、[fields.h:33](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/fields.h:33)

### 8.2 粗到细的半时间步

与粗节点重合的细点，对粗级旧、新两个时刻的三组数据分别平均：

\[
\rho^{n+1/2}=\tfrac12(\rho_c^n+\rho_c^{n+1}),\quad
u^{n+1/2}=\tfrac12(u_c^n+u_c^{n+1}),\quad
f_i^{neq,n+1/2}=\tfrac12(f_{i,c}^{neq,n}+f_{i,c}^{neq,n+1}).
\]

随后重构细分布：

\[
\boxed{f_i^f=f_i^{eq}(\rho,u)+S_{c\to f}f_i^{neq}},\qquad
S_{c\to f}=\frac{\tau_c-1/4}{\tau_c}
=\frac{\tau_f}{2\tau_c}.
\]

源码是逐一平均 `rho,u,fNeq` 后计算平衡分布，不是直接把旧、新完整分布平均。[lagrava.h:75](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:75)

不与粗节点重合的细点，则检查二维 8 个上下文方向，选出满足 `neighborDirection · NORMAL == 0` 且存在重合粗节点及其历史数据的邻居，对这些邻居的半时刻数据平均，再用同一缩放公式。平直二维接口通常就是沿切向的两个端点平均，不是高阶多项式插值。[lagrava.h:99](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:99)、[fields.h:51](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/fields.h:51)

数值例：`tau_c=0.6`，则 `tau_f=0.7`，`S=7/12≈0.583333`。某方向旧、新 `fNeq` 为 `0.002、0.004`，半时刻为 `0.003`，细格重构时添加的非平衡量为 `0.00175`。这是尺度公式的计算示例。

### 8.3 粗到细的完整时间步与历史更新

`FullTimeCoarseToFineO` 使用粗级当前 `rho,u,fNeq`；重合点同时把这些量写回 `PREV_*`，供下一个粗步的半时刻插值。不重合细点依旧取切向可用粗节点的当前数据平均。两种分支使用的粗到细系数相同；非重合分支变量虽然叫 `invScalingFactor`，实际表达式仍是 `(tau_c-0.25)/tau_c`。[lagrava.h:167](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:167)、[lagrava.h:191](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:191)

### 8.4 细到粗：九点滤波只用于非平衡部分

`FineToCoarseO` 先在与粗点重合的**中心细点**计算 `rho,u`。然后对中心和各传播方向邻居的 `fNeq` 等权平均。对于 D2Q9，就是完整的 `3×3` 九点方框：

\[
\overline{f^{neq}_{i,f}}(x)=\frac19\sum_{j=0}^{8}
f^{neq}_{i,f}(x+c_j),
\]

\[
\boxed{f^c_i=f_i^{eq}(\rho_f(x),u_f(x))+
S_{f\to c}\,\overline{f^{neq}_{i,f}}(x)},\qquad
S_{f\to c}=\frac{\tau_c}{\tau_c-1/4}
=\frac{2\tau_c}{\tau_f}.
\]

关键区别：`rho,u` 没有在九点之间平均；九点平均的是每个方向的 `fNeq`，也没有采用 D2Q9 的平衡权重 `w_j`。代码用中心值起步、累加八个邻居，最后除以 `q=9`。[lagrava.h:249](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:249)

从数值作用分析，这个九点空间平均会削弱部分细尺度高频非平衡扰动，在把细网格信息回传给无法表示这些细尺度的粗网格之前起到低通滤波作用。这是本轮找到的最明确的接口滤波；它不是把 `fNeq` 投影为二阶 Hermite 应力，也不是完整的 RLB/HRR 正则化。

### 8.5 接口位置与一步执行顺序

粗到细 coupler 选取细域 frontier 的 `distance=0` 层；细到粗用 `distance=2` 层的重合点，两者并非同一条回写线。外侧层 `distance=-1` 设置为 `NoDynamics`。这里的 distance 是前沿选择器的参数，具体物理位置应按该选择器判定理解。[lagrava.h:286](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:286)、[lagrava.h:323](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:323)、[lagrava.h:362](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:362)

两级情况下，示例时序可简化为：

```text
初始化：缓存粗接口旧时刻 rho/u/fNeq
每个粗步：
    粗格 collideAndStream       获得新粗时刻
    细格 collideAndStream       第一个细步
    HalfTimeCoarseToFineO       用粗旧/新数据补细半时刻接口
    细格 collideAndStream       第二个细步
    FullTimeCoarseToFineO       补细完整时刻接口，更新历史
    FineToCoarseO              九点 fNeq 滤波、缩放并回写粗接口
```

三层示例把相同逻辑嵌到 level 1 的两个子步中，level 2 每粗步共走四步；具体顺序以 [vertexCentered/cylinder2d.cpp:342](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/vertexCentered/cylinder2d/cylinder2d.cpp:342) 为准，不能调换半时刻插值与第二个细步的位置。

### 9.1 通信与插值模板不能拆开移植

`makeCoarseToFineCoupler` 会登记 overlap 中的重合粗细点，使切向插值能找到历史上下文；它还为 `FullTimeCoarseToFineO` 申请 `POPULATION` 通信，并显式登记所需粗格点。每次 coupler `apply` 先执行已注册的粗/细 communicator，再执行各块算子，CUDA 路径最后同步设备。[lagrava.h:299](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:299)、[lagrava.h:308](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:308)、[superLatticeRefinement.h:234](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/superLatticeRefinement.h:234)

对应粗细块有父子匹配时安排在同一个 rank/platform，跨层算子直接访问本地 coarse/fine cell；同层块边界仍需要 halo 通信。因此“交换的数据”包括算子数学上读取/重构的数据和并行通信字段两层意思，不能把 `PREV_*` 都理解成每步跨 MPI 发送的字段。[loadBalancer.h:61](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/loadBalancer.h:61)、[superLatticeRefinement.h:195](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/superLatticeRefinement.h:195)

Lagrava 非重合点平均最后直接除以 `nNeighbors`，这两处分支没有零邻居回退；所以有效法向、重合节点和历史上下文确实存在，是调用方必须维持的前提。本次没有复现失败输入，不把它当作已确认的运行 bug。[lagrava.h:106](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:106)、[lagrava.h:198](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:198)

### 9.2 在这两套接口中没有看到的处理

对这两份算法头文件及其二维调用点逐段检查，没有发现接口自带以下步骤：分布正值性修复、熵条件求解、非平衡幅值自适应裁剪、Hermite 高阶矩投影正则化、HRR 混合重构，或特征波无反射接口。两个二维示例的流体区明确选择 `BGKdynamics`，没有因为启用网格细化而自动替换成 MRT、TRT、CLBM 或熵碰撞。[cellCentered/cylinder2d.cpp:153](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/cellCentered/cylinder2d/cylinder2d.cpp:153)、[vertexCentered/cylinder2d.cpp:118](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/vertexCentered/cylinder2d/cylinder2d.cpp:118)

这不代表 OpenLB 其他目录没有相关碰撞模型；结论范围限于本报告读到的 refinement 耦合路径。也不能仅凭函数名 Rohde 或论文标题，就认定此处所有角点、材料边界和全域积分在任意几何下严格守恒。质量漂移、反射、精度阶和稳定上限仍需分别测试。

物理壁面/入口/出口与粗细接口相交需要特别处理相邻级边界的一致性。OpenLB 开发者在官方论坛也指出，耦合应考虑物理边界条件，或在实际边界单元上禁用；这与当前 coupler 的 bulk 材料筛选相符，但不是对任意边界组合的证明。[官方论坛讨论](https://www.openlb.net/forum/topic/grid-refinement-2/)

### 9.3 网格质量指标不等于动态 AMR 控制器

还有 `SuperLatticeRefinementMetricKnudsen2D`。其局部指标先计算：

\[
C(x)=\frac1q\sum_i\left|\frac{f_i-f_i^{eq}}{f_i^{eq}+w_i}\right|,
\qquad K_{ref}=\frac{Ma}{Re},
\]

再返回截断到非负的 `log2(C/K_ref)`；块级版本先对 `C` 做块内平均。源码没有在这里对指标向上取整，也没有在该函数里重建树或迁移解。[blockLatticeRefinementMetricF2D.hh:43](D:/桌面/代码/代码/热对流/2DRB/openLB/src/functors/lattice/blockLatticeRefinementMetricF2D.hh:43)、[blockLatticeRefinementMetricF2D.hh:78](D:/桌面/代码/代码/热对流/2DRB/openLB/src/functors/lattice/blockLatticeRefinementMetricF2D.hh:78)、[unitConverter.h:191](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/unitConverter.h:191)

所以它可帮助判断哪些块可能分辨率不足；它本身不是稳定器，也不是本次四叉树示例时间循环里的自动细化/退化控制器。

当前两个 **gridRefinement 二维圆柱示例** 使用的是单个 D2Q9 Navier–Stokes lattice；其接口实现没有在同一流程中加入温度分布 `g_i` 的限制/延拓，也没有体现 Boussinesq 浮力跨级交换、温度松弛时间或源项时间居中的完整热对流耦合。[cellCentered/cylinder2d.cpp:30](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/cellCentered/cylinder2d/cylinder2d.cpp:30)、[lagrava.h:75](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:75)

能先提炼的是三层设计：

1. **拓扑层**：四叉树/树森林、2:1 过渡、块边界与粗覆盖区域、同分辨率块合并。
2. **接口算法层**：明确 cell-centered 或 vertex-centered；固定粗细时间尺度；确定交换完整分布还是 `rho/u/fNeq`；将滤波位置、缩放、缓存与时序配套设计。
3. **物理模型层**：对温度平衡分布、热扩散参数、浮力与外源项分别推导，不能因为两套接口都是模板，就视为已覆盖现有的所有流热模型。

如果后续要判断某个接口是否更适合高 Ra，建议先把问题分开验证：均匀流穿过接口的保持、纯剪切/Poiseuille 黏性应力连续性、涡/声脉冲穿越时的反射和耗散、封闭域体积加权质量漂移，以及加入温度后的纯导热通量与浮力平衡。以上是后续验证建议，本次没有修改求解器或提交计算任务。

## 十一、二维四叉树与接口公式速查

以下公式针对本地固定提交的二维 D2Q9 等温流体路径。`l` 表示数值细化层级，`c/f` 表示相邻粗/细级，`h=dx`、`dt` 为物理格距/时间步，`tau=1/omega` 为格子松弛时间。Rohde 的 cell-centered 与 Lagrava 的 vertex-centered 应分别按自己的几何和时序理解。

### 11.1 四分裂、中心偏移与尺度关系

设根块含 `N×N` 个单元、最粗格距为 `h0`。未合并叶块满足：

```text
h_l = h0 / 2^l
L_l = N * h_l                  每个叶块的物理边长
一个父叶 -> 四个子叶           子块逻辑边长减半、l 加 1
```

对于一个中心为 `x_c=(x_c,y_c)`、边长为 `h_c` 的粗单元，其四个子单元中心为：

```text
x_f(sx,sy) = x_c + (h_c/4) * (sx,sy),   sx,sy ∈ {-1,+1}
h_f = h_c/2,    A_f = h_f^2 = A_c/4
```

这里 `x_c` 表示一个粗单元的中心，不是整个粗块的中心；四叉树叶块分裂与单个粗单元对应四个细单元是不同尺度上的两个“四分”。源码通过 `innerOrigin -= delta/2` 移动细块首中心，并以正负象限访问四个子单元。[octant.h:434](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:434)、[octant.h:188](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:188)、[cellCentered.h:41](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/cellCentered.h:41)

`balance()` 的补细化目标可写为邻接叶子 `|l_a-l_b| <= 1`；二维候选邻域包含角邻接，因此不允许 level 0 直接贴 level 2。源码从细到粗收集所需邻居层级，交换跨根请求后补齐树；此处为算法意图概括，未运行结构正确性测试。[root.h:538](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/root.h:538)、[octant.h:789](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/octree/octant.h:789)

每级采用对流尺度换算，并保持同一物理黏度：

```text
h_f = h_c/2,                    dt_f = dt_c/2
u_lattice = U_physical * dt/h   粗细级相同
nu_physical = c_s^2 * (tau-1/2) * h^2/dt

由物理黏度相同得：
tau_f - 1/2 = 2*(tau_c - 1/2)
tau_f = 2*tau_c - 1/2

dt_l = dt0/2^l
tau_l = 1/2 + 2^l*(tau0-1/2)
一个 level 0 步对应 level l 的 2^l 个子步
```

`c_s^2=1/3` 是 D2Q9 的格子声速平方。`tau` 换算由 `convectivelyRefineUnitConverter` 缩小 `dx,dt` 后调用单位换算器实现；Rohde 和 Lagrava 都需要这一物理尺度一致性。[lattice.h:67](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/lattice.h:67)、[unitConverter.h:1593](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/unitConverter.h:1593)、[unitConverter.h:1271](D:/桌面/代码/代码/热对流/2DRB/openLB/src/core/unitConverter.h:1271)

### 11.2 先统一源码分布的符号

用 `F_i` 表示通常 LBM 公式中的分布，用 `p_i` 表示 OpenLB 此处 `cell[iPop]` 中实际存储的数值：

```text
p_i = F_i - w_i
rho = 1 + sum_i(p_i)
p_i^eq = w_i*rho*[1 + 3*(c_i·u) + (9/2)*(c_i·u)^2 - (3/2)*|u|^2] - w_i
f_i^neq = p_i-p_i^eq = F_i-F_i^eq
```

D2Q9 的权重按方向为：静止 `4/9`，四个轴向各 `1/9`，四个对角各 `1/36`。上面的 `rho` 和平衡公式直接对应源码中的 `+1` 与 `-w_i`；比较论文或 Fortran 代码时不能漏掉这一平移。非平衡差值本身不受该常数平移影响。[lbm.h:51](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:51)、[lbm.h:310](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:310)、[lbm.h:396](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:396)

### 11.3 Rohde：分方向复制/四子单元平均与实际推进

`n` 为离散外法向，朝细域外部，角点时可有两个非零分量，不要求单位长度。例如细域内部在接口右侧时，`n=(-1,0)`。判定关键是点积的符号。[discreteNormals.hh:50](D:/桌面/代码/代码/热对流/2DRB/openLB/src/geometry/discreteNormals.hh:50)、[rohde.h:280](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:280)

```text
粗 -> 细：对四个子单元 a，及每个运动方向 i=1..8，
          若 c_i·n <= 0，则 p_i^f(a) <- p_i^c

细 -> 粗：对每个运动方向 i=1..8，
          若 c_i·n > 0，则 p_i^c <- (1/4)*sum_{a=1..4}(p_i^f(a))
```

两套条件不对称：粗到细包含切向 `c_i·n=0`，细到粗只取严格流出方向；静止分布 `i=0` 在这两个算子中都跳过。以平直左接口 `n=(-1,0)` 为例，粗到细复制向右及上下切向的运动分布，细到粗平均向左的运动分布。这不是所有九方向都双向互拷贝。[rohde.h:47](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:47)、[rohde.h:79](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:79)

真实递归推进顺序如下，其中 `K` 是当前级整数步号：

```text
Step(l,K):
    preStepHook(l,K)
    若 l 为最细级：
        collideAndStream(l)
    否则：
        collide(l)
        CoarseToFine(l,l+1)       此时粗级已碰撞、尚未迁移
        Step(l+1,2*K)
        Step(l+1,2*K+1)
        stream(l)
        FineToCoarse(l+1,l)       此时粗级已迁移
```

粗到细只在两个细子步之前调用一次；两个细子步之间没有 Lagrava 式半时刻重构。粗级不能先执行完整 `collideAndStream` 再照搬这套顺序。[rohde.h:317](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:317)

前提是由 `makeCoupler` 设置配套接口动力学：细接口四个子单元使用 `NoDynamicsWithFixedDensityAndVelocity`；粗接口点及其沿 `n` 的邻点使用 `NoDynamicsWithBulkMomenta`；其余被细域覆盖的粗点也禁用普通碰撞，细域外 padding 使用 `NoDynamics`。同时受 bulk 材料与有效邻域筛选约束。只移植上面的复制/平均公式而保留普通接口 BGK 碰撞，并不等价于原算法。[rohde.h:254](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:254)、[rohde.h:269](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:269)、[rohde.h:288](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:288)

**本提交的 Rohde 主耦合没有显式 `tau` 缩放，也没有先拆分平衡/非平衡再缩放。** 两个算子的参数列表均为空，直接操作 `p_i`。每级 `tau` 随单位换算变化，并不意味着接口里还要乘 Lagrava 的非平衡系数。[rohde.h:35](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:35)、[rohde.h:68](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:68)

### 11.4 Lagrava：宏观/非平衡插值与双向系数

令向量 `Q=(rho,u_x,u_y,f_0^neq,...,f_8^neq)`，即源码缓存和重构使用的三组量。对与粗节点重合的细点，半时刻取：

```text
Q_c^(n+1/2) = [Q_c^n + Q_c^(n+1)]/2
p_i^f = p_i^eq(rho^(n+1/2),u^(n+1/2)) + S_cf*f_i^neq,(n+1/2)

S_cf = (tau_c-1/4)/tau_c = tau_f/(2*tau_c)
S_fc = tau_c/(tau_c-1/4) = 2*tau_c/tau_f
S_cf*S_fc = 1
```

完整时刻改用 `Q_c^(n+1)`，并在重合点更新 `PREV_*` 历史。两种粗到细算子中的 `TAU` 都明确传入**粗级**松弛时间。`S_cf/S_fc` 是无滤波、同一非平衡量的代数互逆关系；加入平均、错位插值和不同时间层后，完整延拓/限制操作不是互逆映射。[lagrava.h:75](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:75)、[lagrava.h:167](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:167)、[lagrava.h:335](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:335)、[lagrava.h:264](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:264)

非重合细点从上下文方向中选取 `r·n=0` 的可用重合粗节点。若有效邻居集为 `T`，则：

```text
Q_f^(n+1/2) = (1/|T|)*sum_{r∈T}{ [Q_c^n(r)+Q_c^(n+1)(r)]/2 }
Q_f^(n+1)   = (1/|T|)*sum_{r∈T}{ Q_c^(n+1)(r) }
```

平直二维接口通常是两个切向端点平均。半时刻分支还要求存在邻居历史缓存；代码最后直接除以 `|T|`，因此 `|T|>0` 是前提。这里平均的是 `rho`、`u`、`fneq`，随后重新计算平衡分布；由于平衡分布对速度非线性，这不等于直接平均完整的 `p_i`，也不等于先平均动量 `rho*u` 再除以平均密度。[lagrava.h:99](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:99)、[lagrava.h:191](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:191)

细到粗在重合中心细节点 `x` 计算 `rho_f(x),u_f(x)`，只对非平衡分布做九点等权滤波：

```text
bar_f_i^neq(x) = (1/9)*sum_{j=0..8}{ f_i^neq(x + h_f*c_j) }
p_i^c(x) = p_i^eq(rho_f(x),u_f(x)) + S_fc*bar_f_i^neq(x)
```

每个邻居的 `fneq` 按该邻居自己的宏观量计算。D2Q9 的 `j=0..8` 恰好覆盖 `3×3` 九点，但权重都是 `1/9`，没有采用 D2Q9 的平衡权重 `w_j`；宏观密度和速度取中心，未做九点平均。[lagrava.h:249](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:249)

两级情形的时序为：

```text
初始化缓存 Q_c^n
每粗步：
    coarse.collideAndStream()
    fine.collideAndStream()          第一个细步
    HalfTimeCoarseToFine()
    fine.collideAndStream()          第二个细步
    FullTimeCoarseToFine()           更新历史缓存
    FineToCoarse()                   九点 fneq 滤波、缩放、回写
```

三层时按示例嵌套这一时序，level 2 每最粗步走四步；不能替换成 Rohde 的“粗碰撞—两细步—粗迁移”拆分顺序。接口空间位置也不同：粗到细在细前沿 `distance=0`，细到粗在 `distance=2`，外层 `distance=-1` 使用 `NoDynamics`。[vertexCentered/cylinder2d.cpp:342](D:/桌面/代码/代码/热对流/2DRB/openLB/examples/gridRefinement/vertexCentered/cylinder2d/cylinder2d.cpp:342)、[lagrava.h:286](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:286)、[lagrava.h:333](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:333)、[lagrava.h:362](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:362)

### 11.5 守恒与稳定性主张的边界

Rohde 的四子平均满足一个局部代数关系：对于**已更新的同一方向**，有 `A_c*p_i^c = A_f*sum_a(p_i^f(a))`，且对未平移的 `F_i` 同样成立，因为 `A_c=4*A_f`。但它只回写特定方向，且嵌在碰撞、迁移、接口重叠区及不同时间步中；这个代数关系本身不能证明任意几何/物理边界下的全域总质量严格守恒。全域质量统计还须排除重复覆盖单元，并与物理入流/出流通量对照。[rohde.h:79](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:79)、[rohde.h:317](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/rohde.h:317)、[mesh.h:57](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/mesh.h:57)

Lagrava 在无力、同一宏观矩定义下，各节点 `sum_i(f_i^neq)=0`、`sum_i(c_i*f_i^neq)=0`，因而对这些残差作线性平均和标量缩放，在精确算术下仍不改变重构时指定的局部 `rho,u`；这只是由分解式得到的局部矩性质，不等于跨层体积加权全域守恒，更不能自动扩展为含浮力/热源时的离散守恒证明。[lbm.h:310](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:310)、[lbm.h:396](D:/桌面/代码/代码/热对流/2DRB/openLB/src/dynamics/lbm.h:396)、[lagrava.h:249](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:249)

九点 `fneq` 平均具有空间平滑作用，但这些算子没有显式正值性约束或熵条件，不能仅凭平均/缩放就承诺无负分布或任意 Ra 稳定。Rohde 的方向复制/平均、接口 `NoDynamics` 和拆分时序，与 Lagrava 的节点重合、历史缓存、半时刻重构、非平衡缩放及九点滤波，分别构成配套算法；把两套公式逐项混搭，需要另行推导与验证。

### 11.6 九点非平衡滤波对高频的作用：直接数学推导

对任意一个固定分布方向 `i`，令该非平衡场是傅里叶模态 `f_i^neq(x,y)=a_i*exp(I*(kx*x+ky*y))`，其中 `I^2=-1`，与方向下标 `i` 区分。等权 `3×3` 平均的响应为：

```text
H(kx,ky) = [sum_{rx=-1..1} exp(I*kx*h_f*rx)]
            *[sum_{ry=-1..1} exp(I*ky*h_f*ry)] / 9
          = [1+2*cos(kx*h_f)]*[1+2*cos(ky*h_f)]/9

H(0,0)                 = 1       常数模态保持
H(pi/h_f,0)            = -1/3    单向格点交替模态：幅值为原来的1/3且翻相
H(pi/h_f,pi/h_f)       = 1/9     双向棋盘模态：幅值为原来的1/9
```

这是对 [lagrava.h:256](D:/桌面/代码/代码/热对流/2DRB/openLB/src/refinement/algorithm/lagrava.h:256) 的九点线性算子作出的解析推导，假设完整规则邻域可用；不是算例性能或稳定性验证。它说明部分高频会被削弱，也说明这种均值滤波并非频率响应处处非负的无振荡保证。九点平均本身对非负输入是凸组合，但这里被平均的是可正可负的 `fneq`，随后还要乘 `S_fc` 并与平衡分布相加，所以不能推出重构的标准分布 `F_i=p_i+w_i` 处处非负，也不能推出整个粗细接口算法单调或无反射。
